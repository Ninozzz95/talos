# Final delivery contract — approved Desktop ledger v1

User clarification: the final deliverable is the COMPLETE TALOS APPLICATION in a ZIP, with the approved refactoring compiled and applied. A source patch, partial showcase, ledger or intermediate build is not the final application.

## Mandatory release-candidate gates

1. The complete approved L00-L22 scope has an execution record. Planned, blocked, partly implemented and verified are different states. A green build does not close unimplemented UI/UX work.
2. Build the production frontend from an immutable final commit with the locked dependencies and the declared Node toolchain. Typecheck independently of esbuild.
3. Deliver those exact generated bytes to the application packaging input. Verify every packaged frontend asset against the build manifest, not only the executable's name or package version. The ZIP must not contain stale public assets.
4. Use the actual Desktop packager. Include executable, Electron/Node runtime, local server, compiled frontend, kernel, context engine, native dependencies and required resources. Credentials and GGUF models are not bundled; configure/download them through the normal application.
5. Test a fresh extraction of the ZIP itself on Windows: startup, authenticated local backend, home without the removed introduction, real terminal, workspace navigation, settings persistence, themes and applicable error/recovery flows. No API stub or component showcase can satisfy this gate.
6. Qualify complete separation of demo data, preferences, credentials and application identity from the regular installation (D45), including concurrent operation when supported. Never silently import or alter the regular profile.
7. Record commit, application version, build/toolchain versions, ZIP size, checksum, manifest verification, test results and limitations. Give a working GitHub artifact download plus a conversation copy when delivery permits. An expired or failed attachment is not a delivered artifact.
8. Supply clear extraction/start instructions and the exact source independently. Do not require the user to apply patches or compile the app to use the delivered binary.
9. Merge, release tag, publication as a stable release and installation over the regular application require separate permission (D56).

## Status

This document specifies acceptance. It does not claim that the final ZIP or the full refactoring already exists. The earlier e96c7b8 application is not the final refactored deliverable and must not be relabelled as such.
