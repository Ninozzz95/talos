# Governed extension prototype — development only

This increment stays in PR #24. No merge, tag, release, installer modification,
production import or owner-approval transition is performed. The existing
containment laboratory and its historical verdicts are unchanged.

## Narrow objective

Run a handwritten real WebAssembly **component** in a separate AppContainer
worker, through a bounded Protobuf named-pipe protocol. The trusted prototype
supervisor owns a small immutable byte snapshot and its lease. The guest imports
only the WIT `read` function and computes the sum of the snapshot's bytes. No WASI
filesystem, environment, network, Electron, Node, credentials, activation or
self-modification operation is linked. The component is a test fixture, NOT a
new feature generated by TALOS.

The implementation maps to the proposal's sections 8 (leases), 13 (versioned
ABI), 21 (Wasm + OS + broker), and precedes section 57's installed-product test.
It does not complete the self-extension milestone.

## Authority and lifecycle

`authority.rs` serializes lease admission, consumption, and global byte-budget
charging under one mutex. A lease references 128 OS-random bits and is bound to
an OS-authenticated worker session, component digest, request digest, supervisor
epoch, target, deadline, use count and immutable bytes. Time comes from the
supervisor's monotonic clock, never a message. The grant method is not exposed
over IPC. There is no delegation or persistent authority store in this increment.

The request digest uses a fixed domain and fixed-size component/snapshot SHA-256
digests; it does not hash an assumed canonical Protobuf serialization. Transport
v1 is deliberately strict about alternate/unknown encodings. Prost generates
messages from `contracts/evolution.proto`; Wasmtime parses the WIT at compile
time, and actual component tests exercise its canonical ABI.

A revoked lease cannot authorize a later read. Data already returned cannot be
recalled. Revocation is serialized with admission; it is not retroactive undo.
A failed/terminated worker cannot regain a lease by restarting: the session and
reference are freshly generated. Table and byte budgets are bounded. Poisoned
state, exhausted budgets and invalid messages fail closed.

The Windows adapter assigns a one-process Job **at creation**, checks the token
and Job while suspended, then validates the named-pipe peer PID against the
retained live process and its exact AppContainer SID. The pipe's package ACE
contains data/attribute/synchronization rights, not CREATE_PIPE_INSTANCE. No
ambient handle or parent environment is inherited. A minimal explicit bootstrap
environment is provided. A new, exact-SID AppContainer is mandatory; failure never
falls back to an unrestricted worker. The worker is headless to avoid console
helpers. A failed frame or timeout leads to Job close, observed worker exit and
explicit fixture/profile cleanup.

The guest has fuel, an epoch deadline, stack/linear-memory/table/instance limits
and bounded input/output. Fuel/epochs do not interrupt blocked host I/O: the
supervisor separately bounds pipe operations and owns the process-kill path.
The compiler is Cranelift, not Winch; guest-provided AOT/native deserialization
is never used. Wasmtime LTS 36.0.15 is explicitly pinned (not claimed latest).

## Run in a disposable Windows x64 development environment

With Rust 1.90.0 provisioned and the reviewed Cargo.lock present:

```powershell
$env:RUSTFLAGS = '-C target-feature=+crt-static'
cargo fetch --locked       # trusted dependency provisioning, network permitted
cargo test --frozen -- --test-threads=1
cargo build --bins --frozen
./target/debug/talos-supervisor-prototype.exe --self-test
```

Cargo.lock is checked in from the first measured Windows resolution and was
identical in the following run. The inventory contains 160 packages, including
platform/optional packages (not all are enabled or linked). Its SHA-256 is
`c26580803a064e70f18c1b6f94b1efd228a4ae1b02ae191ab03bd87d2dcbd760`.
CI refuses a missing/changed lockfile and never regenerates it. Provisioning is
still a trusted network step; only compilation/tests subsequently use --frozen.
This is not a claim of OS-enforced offline candidate builds, bit-reproducibility,
or a complete supply-chain/license/security audit. Source/host facts are recorded
before execution. No synthetic positive receipt is checked into source.

Tests cover single-use concurrency, scope/generation/request/epoch mismatch,
expiration, revocation, shared budget, unknown references, real Wasm execution,
unknown imports, excess memory, infinite loops and real separate-worker IPC.
Unsupported platforms can execute pure/engine tests but the executable entry
refuses OS integration. Windows success must come from an actual measured run.

## Explicit remaining boundaries

The fixed supervisor/worker and the official runtime are trusted code at this
stage; only the component is arbitrary. The parent remains a prototype, not the
verified production Supervisor. Both binaries share a Cargo package; dependency
and TCB separation, audited production Windows bindings and a sealed bootstrap
remain later review gates. Filesystem snapshots are synthetic preselected bytes,
not an implementation of general path-safe workspace access.

No claim covers same-user uncontained malware, a compromised OS, official update
root, persistent ledger/recovery, arbitrary Internet/UDP/IPv6, install packaging,
Windows client native-x64 compatibility, side-effect transactions, independent
promotion proofs, or model-driven build/activation. The grant core is tested,
not yet formally proved. Raw test worker output is not a proof verdict.

The app does not import or start this prototype; it is disabled by absence of
production wiring. Never import generated JavaScript into TALOS as a shortcut.
