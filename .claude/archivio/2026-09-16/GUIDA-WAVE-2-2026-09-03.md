## W2-05 — Sandbox policy (K-03)
`sandbox-policy.mjs`: livelli `0 Observe / 1 Native / 2 Container / 3 VM / 4 Remote`; matrice rischio→livello minimo (lettura workspace 1, scrittura 1, rete 2, repo sconosciuto 2, codice non fidato 3); `richiedi(livello)` → backend dal registro o `BLOCKED` (fail-closed, mai downgrade); `app.js` indicatore nel composer accanto alle pillole. Finché K-03 è PENDING vale per la shell diretta e come dichiarazione nella UI. Review 03/09: (a) la matrice valuta ogni argomento e ogni redirect (`< file`, `tac`, `egrep`), non solo il primo programma (Claude Code 2.1.257); (b) un `cd`/cambio cartella non allarga la sandbox (Codex, agosto); (c) livello 1 su Windows = token ristretto + ACL come il sandbox «unelevated» di Codex, che richiede `CreateRestrictedToken`/`CreateProcessAsUser`: helper nativo in `labs/sandbox-windows/`, LABS finché non provato; la via «elevated» (utenti sandbox + firewall) è respinta perché richiede amministratore; (d) livello 2 economico su Windows = backend WSL2 con `bwrap` (W2-03a). Criterio: test al verso contrario (livello non disponibile → blocco; redirect verso file negato → blocco; `cd` fuori workspace → blocco).
