## RED -> GREEN scenarios

### AV-01 - exact bounded contracts

RED: malformed MIME, extension, size, duplicate IDs, unsafe filename, unknown
permission or overlong extracted content is accepted.

GREEN: parser/normalizer tests reject every malformed shape and preserve safe
display names without using them as paths.

### AV-02 - schema v2 and migration

RED: no independent Vault or authority table exists and version-1 bindings have
no migration path.

GREEN: schema tests prove ordered `[1, 2]` upgrades, rebuilt binding table, FKs,
indexes, checks, and exact legacy projection.

### AV-03 - repository authority invariants

RED: repository cannot persist files/grants/bindings or can bind a grant to the
wrong file.

GREEN: memory and real SQLite contract tests prove active matching grants,
atomic message plus binding, cascade semantics, reuse and revocation.

### AV-04 - system picker and private copy

RED: native path is retained, broad permission is requested, cancellation throws,
or `readData` is enabled.

GREEN: picker tests prove metadata-only `pickFiles`; file-store tests prove a
generated private path, count/size limits, cleanup and web/native parity. The
real 8.0.3 picker supports only limit 0/1, so TALOS uses limit 0 and enforces six
files immediately after return, before reading any file data.

### AV-05 - real validation, hash and extraction

GREEN: real `file-type`, PDF.js and Mammoth fixtures plus worker timeout tests;

### AV-06 - two-phase ingestion and recovery

## Amendment 2026-07-22 - multi-file local writer serialization

The first real Playwright multi-file journey exposed a deterministic AV-07
regression: the first selected file became authorized and the second failed,
with the failed identity following array order. The cause is
`useTalosMobileAttachments.ts::selectFiles` starting every Vault ingestion in
`Promise.all`, while each ingestion performs ordered SQLite metadata writes,
private Filesystem writes, analysis and grant writes against the same local
authority boundary.

Add the permanent RED scenario
`useTalosMobileAttachments.test.ts::AV-07 serializes a multi-file picker batch
before writing local storage`. It injects a concurrent-write detector and must
observe at most one active ingestion while retaining both visible draft rows.
Keep all picked drafts visible immediately, but execute `ingestDraft` in picker
order. Do not add retry loops, busy-error matching or database-specific sleeps.

Upstream decision: adapt the application queue at the AVM-owned ingestion
boundary. SQLite's official transaction documentation states that only one
write transaction can run simultaneously and that concurrent write upgrades
can fail with `SQLITE_BUSY`; its isolation documentation explains that writes
are serialized. Sources:

- https://sqlite.org/lang_transaction.html#read_transactions_versus_write_transactions
- https://www.sqlite.org/isolation.html

No package or schema change is required. GREEN requires the named unit test,
the full attachment composable suite and the unchanged Playwright journey with
both text and image authorized in one chooser result.
