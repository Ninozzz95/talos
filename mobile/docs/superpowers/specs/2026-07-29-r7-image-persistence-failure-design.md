# Design - fail-closed generated image persistence

Date: 2026-07-29
Status: ready for RED

## Canonical state transition

```text
provider generation succeeds
  -> Vault save succeeds
       -> existing success result + model image part + durable attachment
  -> Vault save rejects
       -> TALOS_IMAGE_PERSIST_FAILED
       -> no model image part
       -> no message attachment
       -> no automatic save retry or provider regeneration
```

## Result contract

`generate_image` returns the following controlled result when
`TalosImageToolSources.save` rejects:

- `ok: false`;
- `code: TALOS_IMAGE_PERSIST_FAILED`;
- model-visible content says the generated bytes could not be saved and the
  image is unavailable in both chat and Library;
- model-visible content says not to claim success and not to retry or
  regenerate automatically;
- `images`, `messageAttachments`, and fabricated evidence are absent.

The raw exception remains outside model-visible content. Existing executor
audit records the stable tool failure code.

## Compatibility

- provider selection, request, shape, media normalization, and billing behavior
  do not change;
- the successful Vault-save result does not change;
- no repository schema, native Android contract, image renderer, or agent-loop
  interface changes;
- other tools and parallel tool outcomes remain independent;
- the initial bundle budget remains unchanged.

## Human-visible proof

With a test seam that rejects the Vault write after a successful provider
response, TALOS must produce one controlled failure, show no phantom image,
create no Library file or assistant attachment, survive reload without a broken
tile, and issue no second image-generation request.
